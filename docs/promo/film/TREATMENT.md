# TREATMENT · DCTimer 鸿蒙版宣传片

## 0. 一句话

> 一个用鸿蒙原生重写的魔方计时器，把「按下去到出成绩」之间所有等待，压缩成了一个动作。

- **Logline**：屏幕上只有一个数字在涨。停了，成绩落进列表，解法已经在算。全程 40 秒，没有一句旁白。
- **一句话总结影片的「动词」**：**计时**（stopwatch 按下 → 走 → 停 → 落表 → 解）。

## 1. 观众与目的

- 观众：魔方玩家、鸿蒙开发者、想找免费计时器的人。
- 目的：30 秒内让他们知道 ①这是鸿蒙原生应用 ②功能不比 DCTimer 安卓版少 ③界面好看。
- 投放：GitHub README 首屏、B 站、华为应用市场的演示位。

## 2. 三个候选结构（选第三个）

### 候选 A：功能清单式（否决）
九个功能挨个过一遍，每个 3 秒。
*否决理由*：这是最偷懒的写法，观众记不住九件事，且和商店截图完全重复，视频存在的意义被抹掉。

### 候选 B：一天的使用（否决）
早上打乱、中午练 CFOP、晚上看统计。
*否决理由*：40 秒里塞进时间跨度需要大量假装，而本片没有人物、没有叙事主体，会变成一堆转场的堆砌。

### 候选 C：一次完整计时（**采用**）
从「准备」到「成绩落表」到「解法出来」，用一次真实的计时流程串起全部功能。
- 结构：`按下` → `时间流逝` → `停表` → `成绩飞进列表` → `数字滚动出统计` → `解法逐行点亮` → `界面变形为终卡`
- 选它的理由：计时器这个产品最核心的动作就是「按下—等待—停止」，把 40 秒全部押在这一个动作上，观众不需要被教就能理解。其他功能以「顺带出现」的方式被看见，不是被列举。

## 3. 基准（学习什么 / 不学什么）

- **Apple 产品发布片**（黑色舞台、光扫、一屏一句）。**学**：留白比例、单一强调色、大数字独占一屏。**不学**：任何界面、字体、系统控件、音乐。
- **Linear / Vercel 的发布视频**（snap-grid 运动、1px 线、单强调色）。**学**：元素精确落到网格、动效短促带回弹、UI 自己展开成转场。**不学**：具体版式、品牌色、文案。
- **Steve Reich 的过程音乐**（相位、减法）。**学**：音乐层随画面逐条叠加、可数的节拍网格。**不学**：具体旋律。

## 4. 为什么是 `dark-keynote`（暗色科技发布）

DCTimer 本身已经是**沉浸光感 + 毛玻璃 + 深色渐变**的设计，这个风格「近黑舞台 + 界面是主角 + 单一强调色」几乎是它的直接翻译。强调色直接用 App 自己的蓝 `#448AFF`，不引入第二种品牌色。

**和官方 demo 的差异（必须 ≥4 项）**：官方 demo 叫 *Room to Think*（讲办公协作软件）。本片差异——① 题材（魔方计时 vs 协作）② 主角元素（秒表指针/数字 vs 光标）③ 开场（黑底上一个数字开始跑 vs 空白网格）④ 核心 native move（**数字从乱码锁定 + 魔方打乱图的方块塌陷成终卡** vs 光标是主角）⑤ 结尾（界面收缩成一个 App 图标 vs 一个 tile 亮起）⑥ 评分结构（本片是「一次计时」的单线 vs 多场景）。差异 6 项，达标。

## 5. 镜头表（8 个镜头 / 40 秒）

| # | 时长 | 取景 | 镜头运动 | 内容 | 为什么这样拍 |
|---|---|---|---|---|---|
| 1 | 0–4.0s | 特写 | 静止，光从左上扫入 | 纯黑舞台，`DCTimer` 从暗处被光扫亮；下方一行「魔方计时 · 鸿蒙原生」 | 钩子要在 3 秒内给，标题卡也最多 4 秒 |
| 2 | 4.0–9.0s | 中景 | 缓推 | 手机框升起落位，屏内是计时页待机态，`0.00` 呼吸闪烁 | 产品第一次露面，让观众认出「这是个 App」 |
| 3 | 9.0–17.0s | 特写 | 锁死 + 轻微视差 | 手指落下的瞬间变暗，数字开始从 `0.00` 飞速上涨；背景打乱图浮现 | 全片唯一「时间在流动」的段落，节奏由数字自己推动 |
| 4 | 17.0–21.0s | 中景 | 快拉（一拍的 whip pull-out） | 停表，`18.71` 定住并放大到占画面 1/3 高；确认弹窗浮起 | 因果同框：停手 → 成绩 |
| 5 | 21.0–26.0s | 全景 | 横向缓移 | 成绩落进列表，一行行滑入；右侧统计数字滚动 | 「积累」这件事只有列表能表达 |
| 6 | 26.0–31.0s | 中景 | 推入曲线图 | 趋势折线从左往右画出来，平均虚线跟随 | 数据是弧线的，用画的方式比切过去更有说服力 |
| 7 | 31.0–36.0s | 特写 | 推入解法面板 | CFOP 五段逐行点亮：十字 / F2L×4 / OLL；每段步数从左弹出 | 这是 App 最「重」的能力，放在情绪最高点 |
| 8 | 36.0–40.0s | 中景 | 整体收缩 | 界面往中间收，塌陷成 App 图标 + `DCTimer` 字标 + `GitHub · emmm00/DCTimer-HarmonyOS` | 结尾回流到开场，闭合 |

## 7. 转场语法

**唯一的转场方式：界面元素展开 / 收起。** 不用淡入淡出，不用黑帧。
- 镜头 1→2：手机框从底边展开
- 镜头 3→4：数字本体放大成整个画面
- 镜头 4→5：确认弹窗向下展开成列表
- 镜头 6→7：折线图右端延伸出解法面板
- 镜头 7→8：整个界面收缩塌陷

## 8. 声音设计表

| 段落 | 环境层 | 主要 foley | 音乐状态 |
|---|---|---|---|
| 0–4s 开场 | 无（digital zero 的余韵） | 光 shimmer | 单音，逐拍加入 |
| 4–9s 起机 | 极轻的房间底噪 | whoosh / thump / tick | pad 进入，节奏网格建立 |
| 9–17s 计时 | 心跳般的低频 | 密集 tick（数字驱动） | 打击层叠加，逐渐加密 |
| 17–21s 停表 | 无 | 一记 clack | **全停**，只留 clack 的尾音 |
| 21–26s 列表 | 房间底噪回来 | felt tick × 行数 | 旋律层进入 |
| 26–31s 图表 | 无 | 线条生长声 | pad 渐强 |
| 31–36s 解法 | 无 | marimba 五点 | 五声音阶上行 |
| 36–40s 终卡 | 无 | 收缩声 | 一个和弦收束 |

**两处真实静默**：9.0s（按下前）与 17.0s（停表后）。**第一个静默后的声音**是数字开始跳，**第二个静默后的声音**是列表第一行的落表声。

## 9. 字体与字幕

- 英文标题：`Bahnschrift`（系统自带，几何感强，接近 Inter Tight）
- 中文：`Microsoft YaHei`（微软雅黑）
- 等宽数字：`Consolas`
- **本片无旁白、无字幕**（用户明确要求「不用给字幕配音」），只有画面内的功能标签文字。

## 10. 唯一 native move（情绪最高点）

**「数字从乱码锁定」**：镜头 4 停表后，`18.71` 不是直接出现，而是先显示成一串跳动的随机数字（`62.04`、`9.33`、`47.18`…），然后逐位锁定 —— `1`、`8`、`.`、`7`、`1`，每锁定一位弹一下。放在 18.2s，是"等待结束"的那一刻。

## 11. 版权

- 全部画面用代码绘制，不使用任何第三方截图、字体文件、音乐采样。
- 音乐用 numpy 合成（正弦/三角波 + 包络），不采样任何现有作品。
- 音效用 `core/audio/sfx.py` 程序化生成（CC0 由库提供）。
- 字体用系统自带的 Bahnschrift / 微软雅黑 / Consolas，不做嵌入分发。
