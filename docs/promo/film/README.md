# 宣传片 · DCTimer 鸿蒙版

40 秒产品演示片。无旁白、无字幕，只有画面内功能标签、程序化配乐与音效。

## 产出

| 文件 | 规格 | 用途 |
|---|---|---|
| `DCTimer-宣传片-1440p.mp4` | 2560×1440 / 24fps / 13.8 Mbps / ~67 MB | 主交付，华为应用市场演示位、B 站 |
| `DCTimer-宣传片-1080p-分享版.mp4` | 1920×1080 / 24fps / 8.0 Mbps / ~39 MB | GitHub、群聊分享 |

音量已归一到 −14 LUFS（流媒体标准），真峰 −1.2 dBFS。

## 分镜（8 镜头 / 40 秒）

| # | 时间 | 内容 |
|---|---|---|
| 1 | 0–4s | `DCTimer` 字标，光从左上扫过，副标题「魔方计时 · 鸿蒙原生」 |
| 2 | 4–9s | 手机框升起落位，屏内是计时页待机态 `0.00` |
| 3 | 9–17s | 屏幕展开铺满画面，数字飞速上涨，背景打乱图浮现 |
| 4 | 17–21s | 停表 —— `18.71` 从乱码中逐位锁定（全片唯一 native move） |
| 5 | 21–26s | 成绩落进列表，一行行滑入，底部均值栏滚动 |
| 6 | 26–31s | 趋势折线从左往右画出来，平均虚线跟随 |
| 7 | 31–36s | CFOP 六段逐行点亮：十字 / F2L×4 / OLL |
| 8 | 36–40s | 界面收缩，塌陷成 App 图标 + 字标 + 仓库地址 |

两处真实静默：9.0s（按下前）、17.0s（停表后）。

## 怎么做出来的

页面是纯 Canvas 2D 程序化绘制（`index.html`，零图片素材），用 [lemo-opuscar](https://github.com/lemomo-ai/lemo-opuscar) 的 `dark-keynote` 风格引擎逐帧渲染：

```powershell
# 逐帧渲染（960 帧约 40 秒）
node core\render\video.mjs <本目录> --fps 24 --workers 3 --size 2560x1440 --out out\video.mp4

# 静态评审帧
node core\render\still.mjs <本目录> 1.5 8.5 19.0 --size 2560x1440

# 混流 + 响度归一 + 编码
node core\render\mux.mjs out\video.mp4 out\mix.wav DCTimer-宣传片-1440p.mp4 24 2
```

配乐在 `make_audio.py` 里用 numpy 合成（正弦/三角波 + 包络 + 程序化音效），无任何外部音乐素材，无版权问题。

## 设计说明

见 [TREATMENT.md](TREATMENT.md) —— 结构选择理由、与参考片的学习/不学习边界、逐秒节拍表。

风格取自 `dark-keynote`（暗色科技发布）：近黑渐变、发丝网格、柔光、单一强调色、UI 以 snap-grid 精度运动、转场靠元素展开而非淡入淡出。强调色直接用 App 自己的蓝 `#448AFF`，不引入第二种品牌色。

## 修改提示

- 页面只按 `innerWidth` / `innerHeight` 布局（全局尺度 `const S = H / 1440`），任何 `--size` 都能出正确构图。
- 改字号/间距时优先用 `S` 或 `H` 的百分比，别写死像素。
- 中文字体用系统字体（`Microsoft YaHei`），引擎自带字体子集只有约 200 个汉字，标题一换字就会缺。
- 抽帧核对时 `ffmpeg -ss` 要放在 `-i` **之后**才是帧精确；放前面是快进 seek，会跳到关键帧，抽到的时间点是错的。
